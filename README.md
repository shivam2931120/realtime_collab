# Editorial

Realtime document collaboration and team inbox workspace built with:

- React + Vite + TypeScript
- Tailwind CSS
- Zustand
- Tiptap
- Node.js + Express + TypeScript
- Supabase (Postgres)
- Socket.io
- Internal token-based email auth
- EmailJS transactional email

## Project structure

```bash
backend/
frontend/
postman/
docker-compose.yml
render.yaml
vercel.json
supabase_schema.sql
```

## Environment setup

1. Copy env examples:

```bash
cp backend/.env.example backend/.env
cp frontend/.env.example frontend/.env
```

2. Configure backend env (`backend/.env`):

```env
PORT=5000
CLIENT_URL=http://localhost:5173
CLIENT_URLS=
NODE_ENV=development
AUTH_TOKEN_SECRET=replace_with_a_long_random_secret
AUTH_TOKEN_TTL_SECONDS=1209600
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_SERVICE_KEY=your_supabase_service_role_key

# Optional EmailJS for share, mention, and password reset emails
EMAILJS_SERVICE_ID=service_xxxxxxx
EMAILJS_TEMPLATE_ID=template_xxxxxxx
EMAILJS_PUBLIC_KEY=your_public_key
EMAILJS_PRIVATE_KEY=your_private_key
EMAILJS_FROM_NAME=Editorial
EMAILJS_REPLY_TO=
EMAILJS_MIN_INTERVAL_MS=1100

# Optional Redis cache/pubsub
REDIS_URL=
```

3. Configure frontend env (`frontend/.env`):

```env
VITE_BACKEND_URL=http://localhost:5000
VITE_API_URL=http://localhost:5000/api
VITE_SOCKET_URL=http://localhost:5000
```

## Auth flow

- Use `/login` or `/register` for email/password authentication.
- Password auth issues a short-lived signed access token plus a refresh token.
- `/reset-password` completes password reset links delivered by EmailJS.
- `Continue with demo` uses `/api/auth/session` for evaluator access without creating an account.
- Token is stored client-side and sent as `Authorization: Bearer <token>`.
- Backend verifies token signature and derives a stable user ID from email.

## Access roles

- Owner: edit, comment, share, soft-delete.
- Editor: edit and comment.
- Commenter: comment without editing document content.
- Viewer: read-only.

## Deployment checklist

Backend:

```bash
cd backend
npm ci
npm test
npm run build
```

Frontend:

```bash
cd frontend
npm ci
npm run build
```

Set production environment values:

- Backend: `NODE_ENV=production`, `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, `AUTH_TOKEN_SECRET`, `CLIENT_URL`
- Frontend: `VITE_BACKEND_URL` or both `VITE_API_URL` and `VITE_SOCKET_URL`

## Hosting targets

Frontend (Vercel):
- Connect the repo directly. The root `vercel.json` builds `frontend/` and serves `frontend/dist`.
- If you set Vercel's Root Directory to `frontend`, `frontend/vercel.json` has the same install/build/output settings.
- Environment variable: `VITE_BACKEND_URL=https://<render-service>.onrender.com`

Backend (Render):
- Connect the repo and use the included `render.yaml` Blueprint.
- The service root is `backend`, build command is `npm ci && npm run build`, start command is `npm run start`, and health check path is `/healthz`.
- Render prompts for `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, and `CLIENT_URL`. `AUTH_TOKEN_SECRET` is generated by the Blueprint.
- Add `CLIENT_URLS`, `REDIS_URL`, or `EMAILJS_*` in Render only if you need extra frontend domains, Redis, or email notifications.
- Set `CLIENT_URL` to your Vercel production URL, for example `https://your-app.vercel.app`.
