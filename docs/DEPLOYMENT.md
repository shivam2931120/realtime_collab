# Deployment

This repo is set up for a separate frontend and backend deployment:

- Frontend: Vercel
- Backend: Render
- Database: Supabase

## Required Before Deploy

Run `supabase_schema.sql` in your Supabase SQL editor.

## Backend On Render

Use the root `render.yaml` Blueprint when connecting this repository to Render.

Render settings in the Blueprint:

- Root directory: `backend`
- Runtime: Node
- Build command: `npm ci && npm run build`
- Start command: `npm run start`
- Health check path: `/healthz`

Render environment variables:

- `NODE_ENV=production`
- `AUTH_TOKEN_TTL_SECONDS=1209600`
- `AUTH_TOKEN_SECRET` is generated by Render from `render.yaml`
- `SUPABASE_URL` must be entered in Render
- `SUPABASE_SERVICE_KEY` must be entered in Render
- `CLIENT_URL` must be your Vercel URL, for example `https://your-app.vercel.app`
- Add `CLIENT_URLS` only if you need preview/custom frontend domains
- Add `REDIS_URL` only if you add Redis or scale beyond one backend instance
- Add `SMTP_*` variables only if you want email notifications

Manual Render settings, if you do not use the Blueprint:

- Root Directory: `backend`
- Build Command: `npm ci && npm run build`
- Start Command: `npm run start`
- Health Check Path: `/healthz`

## Frontend On Vercel

You can connect the repo as-is. The root `vercel.json` installs and builds from `frontend/`, with output set to `frontend/dist`.

Vercel settings if you choose Root Directory `frontend` instead:

- Install command: `npm ci`
- Build command: `npm run build`
- Output directory: `dist`

Vercel environment variable:

- `VITE_BACKEND_URL=https://<render-service>.onrender.com`

The frontend also supports the explicit pair below, but `VITE_BACKEND_URL` is simpler:

- `VITE_API_URL=https://<render-service>.onrender.com/api`
- `VITE_SOCKET_URL=https://<render-service>.onrender.com`

## Local Checks

Backend:

```bash
cd backend
npm ci
npm run build
npm run start
```

Frontend:

```bash
cd frontend
npm ci
npm run build
npm run preview
```

Smoke check a running backend:

```bash
./scripts/smoke_check.sh http://localhost:5000
```

## Scaling Notes

For one Render instance, Redis can stay empty. Before scaling to multiple backend instances, add Redis and configure sticky sessions or a Socket.IO Redis adapter for realtime fanout.
